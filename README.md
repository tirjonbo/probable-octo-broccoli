# Страницы — сервис печати фотокниг

Интернет-магазин фотокниг с онлайн-редактором: пользователь выбирает продукт, загружает фото, собирает макет в браузере и оформляет заказ с доставкой.

## Возможности

- **Каталог**: фотокниги, фотожурналы, календари, открытки. Для каждого продукта задаются формат, обложка, бумага и число страниц, цена пересчитывается сразу.
- **Онлайн-редактор** (`/editor/:id`):
  - загрузка фото перетаскиванием или через выбор файлов; в браузере фото уменьшаются до 3000 px;
  - автозаполнение: фото равномерно раскладываются по страницам;
  - 6 макетов страницы, подписи, обложка с заголовком, 5 тем оформления;
  - drag-and-drop между страницами (фото меняются местами), на телефоне — выбор касанием;
  - автосохранение, листаемый предпросмотр (стрелки ← →);
  - параметры продукта можно поменять прямо в редакторе.
- **Корзина и оформление заказа**: количество, 3 способа доставки, бесплатная доставка от 5000 ₽, промокоды, подарочные сертификаты с частичным списанием.
- **Подарочные сертификаты**: после оплаты выдаётся код, остаток на нём сохраняется.
- **Аккаунты**: гость может собрать проект без регистрации. При регистрации или входе его проекты и корзина переносятся в аккаунт.
- **Личный кабинет**: история заказов и сохранённые проекты.
- **Админка** (`/admin`): список заказов, фильтр по статусу, смена статуса, базовая статистика.
- Информационные страницы: доставка и оплата, FAQ, контакты.

## Запуск

Нужен Node.js ≥ 22.5 — используется встроенный `node:sqlite`, внешняя БД не требуется.

```bash
npm install
ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD=change-me npm run dev
# http://localhost:3000
```

Тестовый промокод: `WELCOME10` (−10%).

| Переменная | Назначение |
|---|---|
| `DATA_DIR` | Где хранить БД и загруженные фото (по умолчанию `./data`) |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Создаёт администратора (или выдаёт права существующему пользователю) при старте |
| `ALLOW_TEST_PAYMENTS=1` | Разрешает тестовую оплату в production-сборке. В dev она включена всегда |

```bash
npm run typecheck   # проверка типов
npm test            # юнит-тесты цен и автозаполнения
npm run build && npm start
```

## Устройство

- Next.js 16 (App Router) + TypeScript, без UI-фреймворков, стили в `src/app/globals.css`.
- `src/lib/catalog.ts` — продукты, опции, расчёт цены и доставки (общий для клиента и сервера).
- `src/lib/project.ts` — модель макета, макеты страниц, автозаполнение.
- `src/lib/shop.ts` — корзина, итоговые суммы, заказы, сертификаты. **Цены всегда пересчитываются на сервере.**
- `src/lib/auth.ts` — сессии в httpOnly-cookie, scrypt-хеши паролей, гостевые пользователи.
- `src/app/api/*` — REST-обработчики.
- Фото хранятся в `DATA_DIR/uploads`, отдаются только владельцу и администратору. Тип файла проверяется по сигнатуре.
- При оформлении заказа сохраняется снимок макета: правки в редакторе после оплаты в печать не попадут.

## Что нужно доделать до запуска в продакшен

1. **Платёжный шлюз.** Сейчас оплата тестовая (`/api/orders/:id/pay`). Подключить ЮKassa, CloudPayments или Tinkoff: создавать платёж при оформлении и отмечать заказ оплаченным в вебхуке после проверки подписи (`markPaid` в `src/lib/shop.ts`).
2. **E-mail-уведомления**: подтверждение заказа, коды сертификатов, смена статуса, восстановление пароля.
3. **Экспорт макета в PDF для типографии** — генерация print-ready файлов с вылетами по снимку проекта.
4. **Доставка**: расчёт через API СДЭК или Boxberry, выбор ПВЗ на карте.
5. **Хранилище**: при нескольких серверах перенести фото в S3-совместимое хранилище, а SQLite — в PostgreSQL.
6. Юридические страницы (оферта, политика ПДн) и реквизиты в `src/app/contacts/page.tsx`.
